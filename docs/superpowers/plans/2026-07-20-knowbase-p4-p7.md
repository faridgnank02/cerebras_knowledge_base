# P4–P7 Implementation Plan — rerank, expansion, ask pipeline, MCP, web UI

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Complete the query side of knowbase: LLM rerank + context expansion (P4), planner + synthesis `kb ask` with `grep_code`/`who_knows` retrievers (P5), an LLM-free MCP server (P6), and a thin FastAPI web UI (P7).

**Architecture:** All LLM calls go through the Cerebras OpenAI-compatible endpoint using the same injected-fake-client pattern as `Distiller`. Retrieval stays pure functions over `SearchResult`; the P5 pipeline normalizes everything to an `Evidence` schema before synthesis. MCP and web are thin wrappers over existing functions.

**Tech Stack:** Python 3.12, psycopg/pgvector, sentence-transformers (BGE-M3), openai client → Cerebras, typer, `mcp` (P6), FastAPI + uvicorn (P7).

## Global Constraints

- Python `>=3.12` (pinned 3.12 via `.python-version`; uv-managed).
- No RAG frameworks; retrieval is hand-rolled.
- Every LLM call degrades gracefully: rerank failure → RRF order; planner failure → default `["search"]`; synthesis failure → print evidence rows.
- LLM classes take `client=None` and lazily import `openai` so tests inject fakes (see `Distiller`).
- Tests live in `tests/`, run with `uv run pytest`; DB tests use the `clean_db` fixture (Docker Postgres on 5433) and the MiniLM embedder fixture for integration tests.
- Existing behavior of `kb search` / `kb eval` without new flags must not change.

### Task 1: LLM reranker (`retrieval/rerank.py`)

**Files:**
- Create: `src/knowbase/retrieval/rerank.py`
- Test: `tests/test_rerank.py`

**Interfaces:**
- Consumes: `SearchResult` from `knowbase.retrieval.vector`.
- Produces: `class Reranker(base_url, api_key, model, max_doc_chars=1200, client=None, sleep=time.sleep)` with `rerank(query: str, results: list[SearchResult], keep: int = 10) -> list[SearchResult]`. On any failure (2 attempts) returns `results[:keep]` unchanged. On success returns top-`keep` sorted by LLM score desc, original order as tiebreak, with `score` replaced by the 0–10 LLM score.

Schema:

```python
RERANK_SCHEMA = {
    "type": "object",
    "properties": {
        "scores": {
            "type": "array",
            "items": {
                "type": "object",
                "properties": {
                    "index": {"type": "integer"},
                    "score": {"type": "number"},
                },
                "required": ["index", "score"],
                "additionalProperties": False,
            },
        }
    },
    "required": ["scores"],
    "additionalProperties": False,
}
```

Prompt: system = "You score search results for relevance to a query. For each numbered candidate give a relevance score from 0 (irrelevant) to 10 (directly answers the query). Score every candidate." User message = query + numbered candidates (`source_id` + first `max_doc_chars` chars of `document`).

Fallback rules: missing/out-of-range indices ignored; candidates absent from the response keep score 0 but retain original relative order among themselves after scored ones... **No** — simpler and deterministic: candidates missing from the response get score 0.0; final sort key `(-llm_score, original_rank)`.

- [ ] **Step 2: Run tests, verify fail** (`uv run pytest tests/test_rerank.py -v` → import error).
- [ ] **Step 3: Implement `Reranker`** (2 attempts, `sleep(1)` between; parse strict JSON; `replace(r, score=s)`).
- [ ] **Step 4: Tests pass.**
- [ ] **Step 5: Commit** `feat: LLM reranker with RRF-order fallback`.

### Task 3: Context expansion (`retrieval/expand.py`)

**Files:**
- Create: `src/knowbase/retrieval/expand.py`
- Test: `tests/test_expand.py` (uses `clean_db`, seeded rows, no embedder needed)

**Interfaces:**

```python
@dataclass
class Expanded:
    result: SearchResult
    context: str | None = None  # neighbor text, never the hit's own text

def expand(conn, results: list[SearchResult], max_chars: int = 4000) -> list[Expanded]
```

- Burst hit (`metadata.get("kind") == "burst"` — survives canonicalization): context = parent issue row's `raw_content` (full thread), truncated to `max_chars`. Parent id from `metadata["parent"]`.
- Code hit (`source == "github_code"`): neighbors = rows sharing `metadata->>'path'`, ordered by `(metadata->>'start_line')::int`; context = raw_content of the chunk immediately before + immediately after the hit (joined with `\n⋯\n`), truncated to `max_chars`.
- Anything else: `context=None`.
- DB errors: log warning, `context=None` (never break search).

Steps: failing tests (burst → thread; code middle chunk → prev+next; code single-chunk file → None; issue row → None; truncation) → implement → pass → commit `feat: context expansion — adjacent code chunks, full thread for bursts`.
